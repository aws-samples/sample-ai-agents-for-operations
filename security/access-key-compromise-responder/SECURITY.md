# Security Threat Model — AKC Responder (Access Key Compromise Response, Advisory Pipeline)

Generated by the STRIDE Threat Modeler power. Reviewed by Guardian before public publishing.

## Scope

This threat model covers **what actually ships in this repository**: an advisory,
**read-only** serverless pipeline that detects exposed/compromised AWS access keys
(AWS Health, Security Hub/GuardDuty, Trusted Advisor) and invokes the managed AWS
DevOps Agent via an HMAC-signed webhook to investigate and produce **human-run**
containment recommendations. The pipeline **never mutates customer resources**.

Components modeled: 3 EventBridge rules → EventRouter Lambda → AWS Step Functions →
Callback Lambda (HMAC-signed HTTPS webhook to the AWS DevOps Agent Space) → Notifier
Lambda (Amazon SNS email + optional Slack/Teams). Secrets live in AWS Secrets Manager
encrypted with a customer-managed AWS KMS key; failed invocations land in an
Amazon SQS dead-letter queue.

> **Note on the specs.** The `.kiro/specs/` documents describe a different, more
> ambitious two-agent Amazon Bedrock AgentCore design with automated remediation.
> That auto-remediation capability is **not** present in the shipped code. This
> threat model is deliberately scoped to the deployed artifacts (`template.yaml`,
> `pipeline/lambda/*`, the investigation skill, and `README.md`). If the
> auto-mutation design is ever implemented, this model must be re-run — the
> "advisory-only" control (M009) that bounds several threats would no longer hold.

## Detailed Findings

### Spoofing

- **[HIGH] Forged or replayed webhook request** — Component: `pipeline/lambda/investigation_callback/index.py` (Callback → DevOps Agent Space)
  - An attacker who reaches the webhook endpoint (with a weak/empty secret, or by replaying a captured request) starts bogus investigations, driving alert fatigue and masking real compromises.
  - Mitigations: HMAC-SHA256 signing of `<timestamp>:<payload>` with a Secrets Manager secret; **enforce timestamp/nonce freshness on the receiver to defeat replay**. Advisory-only design bounds impact to wasted investigations, not actions.

- **[MEDIUM] Crafted event injection** — Component: EventBridge rules / `pipeline/lambda/event_router/index.py`
  - An identity with `events:PutEvents` or a misconfigured cross-account rule injects a manual/custom event to trigger investigations against arbitrary keys/accounts. (The three AWS sources are reserved and cannot be spoofed directly.)
  - Mitigations: keep rules scoped to reserved AWS sources; restrict `events:PutEvents` on the default bus; validate the extracted `access_key_id` shape (AKIA/ASIA, length) before acting.

### Tampering

- **[HIGH] Manipulated investigation report / prompt injection** — Component: `investigation_callback/index.py` (`_parse_callback`, `_extract_field`, `_extract_table_rows`)
  - A malicious/compromised agent response — or attacker-controlled strings pulled from CloudTrail into the report — feeds the regex Markdown parser, so the responder acts on false findings or misses real resources. Parsing degrades silently (returns `None`) on format drift.
  - Mitigations: treat the report as untrusted — validate parsed fields against the SKILL.md output contract, bound sizes, and neutralize control characters before rendering. Advisory-only design keeps impact to "wrong advice," not "wrong action."

- **[MEDIUM] Log/report content injection** — Component: `notifier/index.py`, DevOps Agent
  - Attacker-seeded user-agents/resource names/paths get rendered into the report or notification body, causing misleading alerts or chat-rendering issues.
  - Mitigations: output encoding before rendering to Slack/Teams/email; PII/content minimization in messages.

- **[LOW] Deploy-time secret leakage** — Component: `template.yaml` `WebhookSecret` parameter
  - Passing the raw secret on the CLI/env during `sam deploy` can leak it via shell history or process listing, despite `NoEcho`.
  - Mitigations: prefer a pre-created Secrets Manager reference over passing the secret through the shell; least-privilege deploy roles.

### Repudiation

- **[MEDIUM] Insufficient attribution of pipeline/response actions** — Components: the three Lambdas, CloudWatch Logs
  - Gaps in logging make it hard to reconstruct who triggered what during an incident.
  - Mitigations: CloudTrail enabled; Step Functions execution history; structured Lambda logs now record HTTP status/host on webhook and notification failures; consider CloudTrail log-file validation.

### Information Disclosure

- **[HIGH] PII exposure via notifications and logs** — Components: `notifier/index.py`, `event_router/index.py`, SNS, Slack/Teams, CloudWatch Logs — **ACCEPTED RESIDUAL RISK**
  - Incident detail plus account alternate-contact PII (names, emails, phone numbers) and the account email travels through notifications and also appears in CloudWatch Logs (the Event Router logs the enriched incident, and the Notifier logs its input). A misdirected SNS subscription, a leaked chat webhook, or CloudWatch Logs access could disclose it and aid social engineering.
  - **Risk decision: ACCEPTED (documented residual risk), no code change.** The account owner name/email and alternate-contact names/emails are **required operational information** — they are how a responder identifies and reaches the owner of the affected account to action a suspected key compromise quickly. Minimizing them out of the message would defeat the notifier's purpose.
  - **Compensating controls that justify acceptance:**
    - **Encryption at rest:** the SNS topic is encrypted (`KmsMasterKeyId`); the two Secrets Manager secrets and the DLQ use a customer-managed KMS CMK with rotation.
    - **Confirmed recipients only:** SNS email delivery requires the subscriber to confirm the subscription, so PII flows only to an address someone actively confirmed.
    - **Encryption in transit:** SNS→email over TLS; Slack/Teams delivery is HTTPS-only (enforced in `_post_json`), and the Notifier logs only the webhook **host**, never the secret-bearing URL.
    - **Least-privilege access:** Lambda roles are read-only/narrowly scoped; CloudWatch Logs access is governed by account IAM.
    - **Advisory-only architecture (M009):** bounds overall impact to disclosure of contact PII, not any mutating action.
  - **Accepted scope explicitly includes the CloudWatch Logs copy of this PII** (Event Router "Received event"/"Normalized incident" lines and Notifier "Notifier input" line). No redaction is applied; the compensating controls above (encrypted transport/at-rest, least-privilege log access, advisory-only) are accepted as sufficient for this content sample.
  - **Risk acceptance:** date 2026-09-25 (follow-up recommendation, LOW residual risk). Re-evaluate if the solution moves beyond a content sample into a production account processing customer data, or if notification channels broaden beyond confirmed SNS subscribers.

- **[HIGH] Disclosure of the HMAC secret / chat webhook URLs** — Data stores: `WebhookSecret`, `Channels` (Secrets Manager), KMS CMK
  - Compromise of a Lambda role, the CMK grants, or the deploy-time parameter exposes secrets that enable webhook spoofing and notification hijacking.
  - Mitigations: Secrets Manager with a customer-managed CMK (rotation enabled); `GetSecretValue` and `kms:Decrypt` scoped to specific ARNs; `NoEcho` on the parameter; protect the KMS key policy.

### Denial of Service

- **[MEDIUM] Detection-event flood** — Components: EventBridge, EventRouter, Step Functions, SQS DLQ
  - A flood of matching events exceeds the per-function reserved concurrency (5), so investigations queue, throttle, or spill to the DLQ — delaying response to a real compromise.
  - Mitigations: reserved concurrency limits blast radius; 14-day SQS DLQ with redrive; add alarms on DLQ depth and Lambda throttles.

- **[MEDIUM] Webhook / notification unavailability** — Components: Callback, Notifier, DevOps Agent, Slack/Teams
  - A down or slow webhook/chat provider causes invocations to fail; without retries a single transient failure drops the investigation or notification.
  - Mitigations: SNS fallback when chat delivery fails; typed error logging added; **add bounded retry/backoff** and an alarm when investigations fail to start.

### Elevation of Privilege

- **[MEDIUM] AWS Organization enumeration via `Resource: "*"`** — Component: `EventRouter` role
  - A compromised EventRouter role abuses the broad `organizations:DescribeAccount` / `ListTagsForResource` and `account:GetAlternateContact` (which don't support resource-level scoping) to enumerate the whole Organization's account names, emails, tags, and contact PII.
  - Mitigations: these read APIs require `Resource: "*"` by IAM design — compensate by keeping the role strictly read-only, monitoring via CloudTrail, and alarming on anomalous Organizations enumeration.

- **[MEDIUM] Pipeline/IaC/KMS-policy tampering** — Components: EventRouter/Callback/Notifier, KMS CMK
  - A principal able to modify the SAM stack, Lambda code, or KMS key policy can exfiltrate secrets, redirect notifications, or (if auto-remediation is ever added) obtain mutating permissions.
  - Mitigations: least-privilege deploy roles, code review, and change monitoring on IaC/code/KMS policy.

## Cross-cutting Control: Advisory-Only Design

The single most important control (M009) is architectural: the pipeline holds **no
mutating permissions on customer resources**, and all containment is performed by a
human after review. This caps the blast radius of the spoofing, tampering, and
privilege threats above at "wrong or wasted advice" rather than "wrong action on
production." Preserving this property is a prerequisite for the residual-risk ratings.
